# Prototype: Tiptap in WebView2

A trial of replacing the editor's RichEditBoxes with one web editor
([Tiptap](https://tiptap.dev), built on ProseMirror) in a WebView2. The toolbar, files and
Markdown stay native, in Rust.

It is separate from the app: its own Cargo workspace and lockfile, and nothing under `src/`,
`vendor/` or `tools/` is changed. It reuses two things read-only:

- `src/markdown` (the app's parser and serializer), compiled in with `#[path]`, so it edits
  exactly the app's SharePoint dialect;
- `vendor/windows-reactor`, for the WebView2 control.

Delete this folder to drop the prototype.

## Run

```
cd prototypes/webview-editor
cargo run -- ..\..\samples\all-features.md
```

(From Claude's shells, run cargo inside `vcvars64.bat`, as for the app.)

The toolbar has the usual formatting, plus:

- **Check round trip**: compares what the editor would save with what the current app saves
  for the file as opened. Use it before editing.
- **Typing benchmark**: types 300 characters at the end of the page, one per frame, and
  reports the time to each painted frame and whether the page ever scrolled up. The document
  is put back afterwards.
- **Dev tools**: the page's browser developer tools.

The status bar shows the current style, the word count, and live timing for real typing
(from key press to the frame that shows it).

`--self-test <file>` opens the file, checks the round trip, runs the benchmark, writes the
results to `%TEMP%\kb-webview-prototype.log` (or `KB_PROTO_LOG`) and exits.

## How it fits together

```
src/main.rs        native window: toolbar, WebView2, status bar, open/save, self-test
src/bridge.rs      app document model  <->  ProseMirror JSON (with round-trip tests)
src/webview/       WebView2 Core bindings, generated by bindgen/ (see bindgen/filter.txt)
web/index.html     the page
web/editor.css     SharePoint-style page on a Word-style canvas
web/editor.js      Tiptap setup, the dialect's extra nodes, the message bridge, timing
web/vendor/        Tiptap bundled into one file (built; checked in so Node is not needed)
```

The app and the page exchange JSON messages (listed at the top of `web/editor.js`). The page
never sees Markdown: the app parses the file with its own parser, sends the document as
ProseMirror JSON, and turns the JSON it gets back into Markdown with its own serializer. Front
matter stays on the Rust side.

Parts of the dialect without a Tiptap editor travel as atom nodes that keep their source and
show it; double-click one to change it:

| Model                     | Editor node                    |
| ------------------------- | ------------------------------ |
| `[[Page]]` link           | `pageLink` mark                |
| `$x$`, `$$ … $$`          | `mathInline`, `mathBlock`      |
| `:::image …:::`           | `media` (shows the image)      |
| Raw Markdown              | `rawInline`, `rawBlock`        |
| Table column alignments   | an attribute on `table`        |

## Rebuild the editor bundle

Needs Node.js. In `web/`:

```
npm ci
npm run build
```

## Results so far

From `--self-test`, debug build, on this machine:

| File                          | Round trip vs. current app | Benchmark (median / 95th / max) | Scrolled up |
| ----------------------------- | -------------------------- | ------------------------------- | ----------- |
| all-features.md               | identical                  | 16.7 / 17.4 / 88.7 ms           | 0           |
| Knowledge Base Article Writer | identical                  | 16.7 / 17.2 / 17.8 ms           | 0           |
| employee-handbook.md          | identical                  | 16.7 / 17.3 / 17.9 ms           | 0           |
| 130 KB, 1,240 blocks          | identical                  | 16.7 / 18.0 / 20.6 ms           | 0           |

16.7 ms is one frame at 60 Hz: each character showed on the next frame. The benchmark
inserts characters through the editor rather than through the keyboard, so it does not
include input handling. The status bar's live timing does.

## Not in the prototype

- Ribbon buttons do not yet show the selection's state (the status bar does, as text). The
  state arrives in the `state` message, so wiring it up is native-only work.
- No Navigation pane, find and replace, zoom setting, or close-with-unsaved-changes prompt.
- Math shows as LaTeX source and Mermaid as code (KaTeX and Mermaid can render both on the
  page).
- Links do not open on click.
- Dark page theme.
